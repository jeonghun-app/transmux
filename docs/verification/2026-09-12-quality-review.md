# 수집 경로 품질 점검 — 2026-09-12

RTSP → HLS → S3 수집 기능을 대상으로 결함을 수정하고 검증했다. 전달 계층이나
녹화 조회 API를 추가한 작업은 아니다.
후속 솔루션 구현과 검증은 [별도 기록](2026-09-12-solution-review.md)에 정리했다.

## 수정 내용

| 영역 | 확인한 문제와 수정 |
|---|---|
| 설정·카메라 목록 | `-validate`에 정적 카메라 검증과 중복 검사를 적용했다. 잘못된 URL·객체 prefix와 시간 계산 오버플로를 거부한다. HTTP 목록의 `null`, 잘린 대용량 응답, 알 수 없는 필드를 오류로 처리해 기존 채널이 사라지지 않게 했다. |
| 자격증명 | 잘못된 RTSP URL의 파싱 오류와 저장소 설명에서 자격증명이 노출되지 않게 했다. AWS 기본 자격증명 체인을 사용해 임시 자격증명의 세션 토큰을 보존한다. |
| 소유권 | lease schema·필수 필드·ETag를 확인한다. 응답과 확인 읽기가 함께 실패한 쓰기의 식별자를 다음 시도까지 보존한다. 자기 쓰기를 다른 소유자의 쓰기로 오인해 영구 정지하는 문제를 수정했다. |
| 갱신·종료 | lease 요청에 별도의 제한된 동시성을 부여했다. 만료된 소유자의 세그먼트 업로드를 막고, 이전 세대의 마지막 업로드 중 소유권을 잃으면 새 ffmpeg를 시작하지 않는다. 여러 채널을 제거할 때 종료를 동시에 시작한다. |
| HLS·스풀 | 잘못된 duration, 잘린 복구 매니페스트, 모순된 시퀀스와 지원하지 않는 태그를 거부한다. 유실된 구간을 재시도마다 중복 집계하지 않으며 다음 세그먼트에 discontinuity를 표시한다. 대체 PDT 기록의 메모리 사용도 제한한다. |
| 프로세스·모니터링 | 긴 stderr 때문에 ffmpeg가 멈추지 않게 계속 읽는다. 매니페스트가 발행되지 않는 채널은 비정상으로 판단하며 첫 발행 실패부터 지연을 계산한다. 채널 생성과 메트릭 수집이 겹칠 때의 초기화 경쟁과 Prometheus 이스케이프를 수정했다. |
| 저장소·배포 | 파일시스템 CAS 대기가 요청 취소를 따르며 HEAD가 이전 객체의 메타데이터를 반환하지 않게 했다. 컨테이너 종료 유예를 45초로 늘렸다. PoC 검증은 정상 발행을 기다리고 실제 프레임까지 디코딩한다. |
| 도구·의존성 | Go 1.26.8 / Alpine 3.23으로 갱신했다. 보안 검사에서 발견한 `GO-2026-5764`를 S3 SDK 1.97.3 / eventstream 1.7.8로 수정했다. 포맷 검사와 재현 가능한 취약점 검사 타겟을 추가했다. |

## 검증 결과

다음 검사가 모두 통과했다.

```bash
make fmt-check vet test race build vuln
make test-ffmpeg image IMAGE=transmux-review VERSION=review-20260912
```

- 모듈 무결성 확인 성공, `govulncheck`: `No vulnerabilities found`.
- 새 런타임 이미지에서 `configs/poc.json`의 `-validate` 성공.
- 테스트 함수 149개에서 183개로 증가했다. 테이블의 하위 사례는 별도다.
- ffmpeg 8.0.1 통합 테스트: 실제 H.264 세그먼트 생성, 긴 GOP 처리, 프로세스 그룹 종료.

별도 Compose 프로젝트에 테스트용 카메라·MediaMTX·MinIO·데몬 두 개를 실행해
다음 장애 시나리오를 검증했다. 호스트 포트를 열지 않았고 테스트 데이터와
컨테이너는 검증 후 정리했다.

| 시나리오 | 결과 |
|---|---|
| 정상 수집·재생 | 두 채널 정상. 매니페스트가 참조하는 객체 전부 존재. H.264 프레임 디코딩 성공. 실제 세그먼트 길이 각각 4초·8초. |
| MinIO 8초 중단 | 두 채널 모두 ffmpeg 재연결 0, 세그먼트 유실 0, 복구 후 시퀀스 증가. |
| 짧은 GOP 카메라 중단·재기동 | 대상 채널 재연결 1회, 유실 0. 다른 채널은 정상 수신 유지. |
| 체크포인트 없는 컨테이너 교체 | 긴 GOP 시퀀스 13 → 15, 짧은 GOP 27 → 30. 저장된 매니페스트에서 복구. |
| 두 데몬에 동일 카메라 할당 | 대기 데몬의 두 채널 모두 `waiting_ownership`, ffmpeg PID 0. |
| 소유 데몬 pause 후 인수·재개 | 새 소유자 시퀀스 15 → 17 / 30 → 35. 이전 소유자는 두 채널 모두 `failed`, ffmpeg PID 0. 인수 후 객체 정합성과 디코딩 재검증 성공. |
| 정상 종료 | 두 데몬 모두 종료 코드 0. 검증용 컨테이너·네트워크·볼륨 정리. |

## 검증의 범위

실제 운영 카메라, 실제 AWS S3의 IAM·네트워크 구성, 장시간 부하 및 625채널 예시의 용량은
이번에 검증하지 않았다. 기존 용량 수치는 이전 ffmpeg·Go 환경에서 측정한 값이다.

저장소 장애 허용 시간은 lease 만료 시간의 영향을 받는다. 이번 장애 검증은 PoC의
TTL 20초보다 짧은 8초 중단이다. 갱신 실패로 소유권이 만료되면 기존 안전 정책대로
채널은 `failed`가 되며 데몬 재시작이나 카메라의 로스터 제외·재등록이 필요하다.

이 수집 점검 시점에는 시청자 인증·과거 영상 조회·오디오가 미구현이었고 H.265
재생을 검증하지 않았다. 후속 솔루션 작업에서 이를 구현·검증했으며, 현재 제품
범위는 [기존 미디어 서버에서의 전환](../wowza-coverage.md)을 참고한다.
