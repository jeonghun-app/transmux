# 관제·녹화 솔루션 검증 — 2026-09-12

수집 전용 프로젝트를 인증된 라이브·녹화 재생, MP4 내보내기, 카메라 관리와
운영자 화면을 갖춘 구성으로 확장했다. 이전 수집 안정성 수정은
[수집 품질 점검](2026-09-12-quality-review.md)에 별도로 기록했다.

| 구성 | 검증 환경 |
|---|---|
| Go / 기반 이미지 | Go 1.26.8, Alpine 3.23 |
| 미디어 | ffmpeg 8.0.1, MediaMTX 1.21.0, 실제 합성 RTSP |
| 저장소 | 비공개 MinIO, 수집·재생과 별도 컨테이너 |
| 클라이언트 | 로컬 HLS.js 1.7.3, Playwright 1.63.0, Chromium 153.0.8010.12 |

| 영속 상태 | S3 객체, 공유 카메라 목록, bbolt 시간 인덱스·VOD 목록 |

## 자동 검사

다음 검사가 통과했다.

```sh
make fmt-check vet test race build vuln
make test-ffmpeg
python3 scripts/verify-solution.py --restart
```

의존성 갱신 후 `vet`, race 전체 테스트, 두 바이너리 빌드, 실제 ffmpeg 통합 검사를
다시 통과했다. 모듈 무결성 검사 성공, 최종 `govulncheck`는
`No vulnerabilities found`를 반환했다.
간접 의존성 `x/sys`도 v0.44.0으로 갱신해 사용하지 않는 Windows 패키지에 있던
`GO-2026-5024`까지 해소했다. UI 검사 패키지의 npm audit도 알려진 취약점 0개였다.

수집·재생 솔루션 설정의 `-validate`, JSON·Python·워크플로 YAML 구문도 확인했다.
CI에는 단위·race·ffmpeg·설정 검사와 비공개 저장소·재시작·브라우저 검증 작업을
추가했다. CI 정의는 로컬 검증과 같은 명령을 사용하며 원격 Actions 실행 결과는 아니다.

주요 테스트 범위:

- 카메라 원장의 최초 생성 경쟁, 동시 편집 충돌, 샤드 필터·배정 이동.
- TS·fMP4 파싱, 초기화 파일 선행 업로드, 날짜별 초기화 복사, 저장 실패 시 발행 차단.
  HEVC의 `hvc1` 표시와 잘못된 코덱·컨테이너 조합 거절.
- 시각 인덱스의 자정·단절·중복·쿼리 제한·영속 복구·커서·늦은 객체 재검사.
- VOD 목록의 고정·정확한 객체 권한·갱신·만료·용량 제한.
- JWT 알고리즘·issuer·audience·종류·만료·센터·카메라·작업 권한.
- 비밀 RTSP 주소 비노출, 내부 모니터링 경로 비공개, CORS·Range·경로 제한.
- MP4 작업·실제 디코딩·취소, 자신의 미디어만 삭제하는 보존 처리.

## RTSP에서 재생·파일 다운로드까지

저장소의 메타데이터만 확인하지 않고 라이브 HLS·녹화 HLS·완료된 MP4에서
실제 영상·음성 프레임을 ffmpeg로 디코딩했다.

| 카메라 | 입력 → 출력 | 실제 조각 길이 | 초기화 MAP | MP4 크기 | 결과 |
|---|---|---|---|---:|---|
| 정문 | H.264/AAC → MPEG-TS, AAC 복사 | 4초 × 4 | 0 | 2,149,110 B | 라이브·녹화·MP4 디코딩 성공 |
| 창고 | H.264/G.711 → fMP4/AAC | 8초 × 4 | 1 | 4,413,552 B | 라이브·녹화·MP4 디코딩 성공 |
| HEVC | H.265/G.711 → fMP4/AAC | 4초 × 4 | 1 | 722,854 B | 라이브·녹화·MP4 디코딩 성공 |

파일 크기는 이 실행의 표본이며 고정 비트레이트·용량 보장 값은 아니다.
ffprobe로 HEVC 라이브·MP4의 `hvc1`, H.264 MP4의 `avc1` sample entry도 확인했다.

- 비공개 S3 미디어의 익명 요청은 403.
- 인증 없는 카탈로그는 401, 다른 카메라 capability와 시청자의 내보내기는 403.
- 제어 객체를 미디어 경로로 요청하면 404.
- 인증된 `Range: bytes=0-15`는 206과 정확한 16바이트.
- 영상 조각에는 `transmux-kind=segment`, 초기화에는 `transmux-kind=init`.
  라이브 매니페스트·lease·루트 카메라 목록에는 보존 태그가 없음.
- Lifecycle JSON을 모의 MinIO에 가져오고 다시 내보내 정책 수용을 확인했다.
  실제 30일·32일 만료까지 기다려 삭제를 관측한 검증은 아니다.

## 재시작

`verify-solution.py --restart`는 기존 VOD URL과 본문을 확보한 뒤 컨테이너를
재생성한다. 서명 키와 영속 볼륨을 유지하는 실제 Compose 경로를 사용했다.

| 항목 | 결과 |
|---|---|
| playbackd 재생성 | 기존 VOD URL이 같은 매니페스트를 반환 |
| 기존 capability | 재시작 뒤에도 허용 객체의 Range 요청 성공 |
| transmuxd 재생성 | HEVC 시퀀스 433 → 436, 재시작 이후 캡처 시각 확인 |

카메라·저장소 장애, 중복 수집기와 동결 소유자 인수의 이전 검증은
[수집 품질 점검](2026-09-12-quality-review.md)을 따른다. 이 표는 미디어 공백 0초를
보장하는 측정이 아니다.

최종 종료에서도 수집·재생 프로세스 모두 exit code 0, OOM 없음으로 확인했다.
`make solution-down`으로 검증 컨테이너·네트워크를 정리하고 녹화·설정·인덱스
볼륨은 보존했다. 생성한 자격증명이 Git 대상 파일에 포함되지 않은 것도 확인했다.

## 브라우저

기본 HLS.js 경로에서 실제 H.264 MPEG-TS·fMP4 두 영상을 재생하고 프레임 수와
`videoWidth`를 확인했다. Chromium의 내장 HLS 대체 경로에서도 실제 프레임을 확인했다.
로딩 속성 때문에 내장 플레이어가 영원히 대기하던 오류를 이 과정에서 수정했다.

전체 사용자 흐름 7개가 통과했다(최종 실행 27.6초).

| 시나리오 | 확인한 결과 |
|---|---|
| 로그인 | 잘못된 비밀번호 안내·입력 보존, 지연 중 Enter·클릭 중복 제출 차단, 버튼 폭 유지 |
| 라이브 | H.264 TS·fMP4 두 카메라의 실제 프레임, 전체 닫기와 선택 해제 |
| 내장 HLS | HLS.js를 사용할 수 없을 때 내장 플레이어의 실제 프레임 |
| 녹화·MP4 | 실제 녹화 재생, 작업 완료 후 일반 GET 다운로드, Blob을 사용하지 않음 |
| 카메라 관리 | 중복 저장 차단, 비밀 주소 비노출·Escape 포커스, HEVC/fMP4 선택 연동, 새 RTSP 수집·재생·중지 |
| 계정·화면 | 로그아웃 시 이전 결과·입력한 비밀 주소 제거, 시청자의 관리·추출 제한, 320·390·768px 가로 넘침 없음 |
| 오류·경합 | 목록 갱신 실패에도 기존 목록 보존, 조건 변경 전의 늦은 녹화 응답 무시 |

로그인·라이브·녹화·모바일 화면의 axe WCAG A/AA 자동 검사에서 위반 0건이었다.
자동 검사와 실제 키보드 경로 확인은 모든 보조기기의 수동 검사를 대신하지 않는다.
라이브·녹화 화면 캡처를 직접 확인했다.

다음 명령으로 재현할 수 있다.

```sh
cd tests/browser
npm ci
npx playwright install chromium
npm test
```

테스트는 실제 미디어를 사용한다. 로그인 지연·실패, 목록 갱신 실패와 늦은 녹화
응답만 선택적으로 주입하여 오류·경합 처리를 확인한다. 토큰·로그인 본문을 남길 수
있는 Playwright trace는 저장하지 않는다. 화면 캡처는 `tests/browser/artifacts/`에
생성하며 Git에는 포함하지 않는다.

## 운영 검증의 경계

실제 운영 카메라·단말, 외부 인증 체계, AWS IAM·네트워크, 625채널 예시·30일 보존의
장기 부하는 검증하지 않았다. HEVC의 ffmpeg 디코딩은 모든 브라우저 지원을
뜻하지 않는다. WebRTC·LL-HLS·방송용 ABR, 재생 서버의 공유 상태·완전한 HA는
현재 구현 범위 밖이다.

이번 결과는 모의 스택에서 기능과 오류 처리를 확인한 기록이다. 전환 대상별 조건과
단계적 이행은 [기존 미디어 서버에서의 전환](../wowza-coverage.md)을 따른다.
