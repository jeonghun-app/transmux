# ADR 0003 — 카메라 관제·녹화 솔루션

- 상태: 구현됨
- 날짜: 2026-09-12
- 선행: [ADR 0001](0001-architecture.md), [ADR 0002](0002-delivery-playback.md)

## 문제

RTSP를 S3에 저장하는 수집기만으로는 관제용 Wowza를 교체할 수 없다.
운영자가 권한 있는 카메라를 보고, 과거 녹화를 찾고, 영상 파일을 추출하며
수집 대상을 관리하는 경로까지 필요하다. 사용자 트래픽과 인덱스 장애가
카메라 수집을 멈추게 해서는 안 된다.

## 결정

`transmuxd`는 영상 복사·소유권·저장에 집중한다. 별도 `playbackd`가
인증, 카탈로그, HLS 전달, 녹화 인덱스, 관리 API와 운영자 화면을 담당한다.
수집 성공 경로에서 재생 서버나 인덱스 DB를 호출하지 않는다.

### 비공개 저장소와 인증 프록시

첫 배치는 사설 S3에서 영상을 읽는 인증 프록시다. 공유 서명 키를 가진
중앙 백엔드 또는 자체 운영 계정이 센터·카메라·작업 범위의 API 토큰을 발급한다.
재생 세션은 별도 audience와 짧은 만료를 가진 URL capability를 발급한다.

토큰은 `/media/{token}/{center}/{camera}/` 경로에 둔다. HLS의 상대 URI가
같은 경로 아래로 해석되므로 브라우저와 네이티브 플레이어가 영상·초기화 객체에도
권한을 전달한다. 매 요청의 범위·만료를 검사하며 쿼리 문자열 상속이나
플레이어 전용 Authorization 헤더에 의존하지 않는다.

이는 ADR 0002의 CloudFront 서명 쿠키 제안을 대신한다. 현재 서버는 공유 캐시를
사용하지 않으며 미디어 응답에 `private, no-store`를 적용한다. TLS 종단,
프록시 경로 로그 마스킹, 외부 인증 연동은 운영 구성의 책임이다.

### 지속 가능한 녹화 조회

S3 메타데이터를 원본으로 삼고 별도 영속 bbolt 인덱스에 카메라·UTC 날짜별로
시각과 시퀀스를 저장한다. 라이브 추적과 과거 복구에 별도 작업 풀을 할당해
대량 복구 중에도 새 영상이 조회되게 한다. 목록 페이지의 커서를 저장하고
겹친 꼬리와 주기적 전체 재검사로 늦은 객체를 복구한다.

시청자 조회는 이 인덱스를 사용한다. S3 전체 List/HEAD를 조회마다 실행하지 않는다.
발급된 VOD의 매니페스트와 정확한 허용 객체 목록을 별도 세션으로 고정한다.
이후 인덱스 복구가 이미 재생 중인 목록을 바꾸지 않게 한다.
세션 갱신은 같은 목록의 만료만 연장한다.

첫 배치는 한 재생 프로세스와 영속 인덱스다. 외부 DB·이벤트 기반 인덱서와
공유 세션 저장소는 실제 규모·HA 요구가 정해졌을 때 교체할 경계로 남긴다.
현재 인덱스는 다중 프로세스 공유 파일이 아니다.

### 영상·음성과 내보내기

영상은 계속 `copy`한다. 카메라별로 MPEG-TS 또는 fMP4를 선택하며
음성은 `none`, `copy`, `aac` 중 선택한다. G.711의 AAC 변환은 영상
재인코딩과 구분되는 명시적 비용이다. fMP4 초기화 파일은 내용 해시와
캡처 날짜로 구분하고 미디어보다 먼저 저장한다.

MP4는 권한을 확인한 비동기 작업으로 만든다. 입력 크기·시간·디스크 여유·동시
작업 수를 제한하며 로컬 HLS를 영상·음성 복사로 remux한다. 준비된 파일은
짧은 capability를 통해 Range 지원 GET으로 다운로드한다.
브라우저가 대형 파일 전체를 Blob으로 보관하지 않는다.

### 공유 목록과 보존

카메라 원장은 S3의 작은 JSON 객체다. 최초 목록은 조건부 생성하고 이후 수정에는
ETag를 요구한다. `shard_id`와 각 수집기의 필터로 담당 서버를 배정하며
실제 소유권 이전은 기존 lease·매니페스트 fence가 보호한다.
수집 중지는 목록 항목을 비활성화하여 과거 녹화를 계속 조회할 수 있게 한다.

삭제는 기본 비활성화다. 서버 정리 작업은 자신의 미디어 경로와 메타데이터를
검증한 뒤 오래된 날짜만 순회한다. 대규모 S3에는 선택적 미디어 태그와
Lifecycle 예시를 제공한다. lease·목록·라이브 매니페스트는 삭제 대상이 아니다.

## 결과와 제약

라이브·녹화·내보내기·관리까지 실행 가능한 단일 관제 구성을 제공한다.
비공개 버킷과 실제 RTSP·ffmpeg·브라우저 검증을 함께 제공한다.

대가로 프록시 대역폭, 인덱스 디스크, 오디오 변환·내보내기 CPU를 별도로
산정해야 한다. HEVC 웹 재생은 단말 디코더에 의존한다. 재생 서버의 완전한
HA·CDN 캐시·초저지연·프레임 단위 절단은 포함하지 않는다.
현재 규모 검증으로 625채널·8GB·30일 운영을 보장하지 않는다.

실행 계약은 [솔루션 가이드](../solution.md), 전환 조건은
[Wowza 대체 범위](../wowza-coverage.md)를 따른다.
